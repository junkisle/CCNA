## Configuration Mode and Subconfiguration Mode

### Global Configuration Mode
Mode used to configure the device
- Accessed before other specific configuration modes
- Identified by a prompt that ends with:
```
(config)#
```

From global config mode, the user can enter different subconfiguration modes.
### Line Configuration Mode
Used to configure console, SSH, Telnet, or AUX access
```
Switch(config-line)#
```
### Interface Configuration Mode
Used to configure a switch port or router network interface
```
Switch(config-if)#
```
## Navigate Between IOS Modes
To move from user EXEC mode to privileged EXEC mode, **enable** command is used. **Disable** command to return to user EXEC mode.

**Configure terminal** - used from privileged exec mode to enter **global configuration mode**. Use the command **exit** to return to privileged EXEC mode.

To enter a subconfiguration mode, use **line** command followed by the management line. Use **exit** to exit to return to global config mode

# Basic Device Configuration

## Device Names
### Naming standard to identify network devices
- Start with a letter
- Contain no spaces
- End with a letter or digit
- Use only letters, digits, and dashes
- Less than 64 characters in length

### Naming convention
Easily identify a specific device
![[Pasted image 20260810115218.png]]
```
Switch# configure terminal
Switch(config)# hostname Sw-Floor-1
Sw-Floor-1(config)#
```

## Password Guidelines
- More than eight characters in length
- Combination of upper and lowercases, numbers, special characters
- Avoid using same password for all devices
- Avoid using common words

## Configure Passwords
### Secured user EXEC mode

^cd1ae2

When you initally connected to a device, you are in user EXEC mode.

To secure user EXEC mode access, enter console configuration mode using **line vty 0**. 0 is used to represent the first (and in most case the only) console interface.

#### **password** *password*
Command to add a password to **user EXEC mode**

```
Sw-Floor-1# configure terminal
Sw-Floor-1(config)# line console 0
Sw-Floor-1(config-line)# password cisco
Sw-Floor-1(config-line)# login
Sw-Floor-1(config-line)# end
Sw-Floor-1#
```

#### **enable secret** *password*
Command to secure **privileged EXEC mode**
```
Sw-Floor-1# configure terminal
Sw-Floor-1(config)# enable secret class
Sw-Floor-1(config)# exit
Sw-Floor-1#
```

#### Securing Virtual Terminal (VTY) lines
Virtual Terminal Lines enable remote access using Telnet or SSH
- Cisco switches support up to **16 VTY lines**
```
Sw-Floor-1# configure terminal
Sw-Floor-1(config)# line vty 0 15
Sw-Floor-1(config-line)# password cisco
Sw-Floor-1(config-line)# login
Sw-Floor-1(config-line)# end
Sw-Floor-1#
```

## Encrypt Passwords
The startup-config and running-config display most passwords in plaintext. ^2056f9

#### **service password-encryption**
To encrypt all plaintext passwords, use this global config command
```
Sw-Floor-1# configure terminal
Sw-Floor-1(config)# service password-encryption
Sw-Floor-1(config)#
```

# Save Configurations

### startup-config
Saved configuration file stored inside the NVRAM. Contains all the files that will be used open restart or boot. Flash does not lose its contents when powered off

### running-config
Stored in the RAM. Reflects current configuration. Modifying this affects the device immediately. Loses all of its content upon shutdown or restart.

### [Privileged EXEC mode] show running-config
**Privileged EXEC mode** command used to view the running config.


To save changes made to the running configuration to the startup configuration file, use the command:

### [Privileged EXEC mode] copy running-config startup-config

## Altering the Running Configuration

### [Privileged EXEC mode] reload
restores the device to its previous configuration

### [Privileged EXEC mode] erase startup-config
Erases the entire startup configuration. Used when necessary to clear all the configuration

# Ports and Addresses
## IP Addresses

The use of IP address is the primary means of enabling devices to locate one another and establish end-to-end communication on the internet. Example of these are:

- Computers (work stations, laptops, file servers, web servers)
- Network printers
- VoIP phones
- Security cameras
- Smart phones
- Mobile handheld devices (such as wireless barcode scanners)

### IPv4 Address
The structure of an IPv4 address is called the **dotted decimal notation**.
- Represented by decimal numbers between 0 and 255.

### Subnet mask
A 32-bit value that differentiates the network portion from the host portion
- Couple with the IPv4 address, the subnet mask determines which subnet the device is a member
![[Pasted image 20260824100610.png]]


### IPv6
**128 bits** in length and written as a string of **hexadecimal** values
- Every four bits are represented by a single hexadecimal digit for a total of 32 hexadecimal values
- Groups of four hexadecimal values are separated by a colon (:)
- NOT case-sensitive

## Interfaces and Ports

Cisco IOS Layer 2 switches have physical ports for devices to connect. These ports do not support Layer 3 IP addresses.

### Switch Virtual Interface (SVI)
Virtual Interfaces because there is no physical hardware on the device associated with it.
- Created in software
- Allows the user to manage the switch remotely using IPv4/IPv6
- Each switch comes with one SVI appearing in the default configuration.
	- The default SVI is interface VLAN1
